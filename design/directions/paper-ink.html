How it works

Three moves,
then the note ships.

Nothing here is a star rating. Every note is attached to a category, a severity and a version, which is what lets a creator sort them instead of read them.

  • 01

    Post the build

    A link, a cut, a build or a draft, plus the grit step it is at. The step decides which questions the composer puts in front of a reviewer, so nobody sends a concept the notes a release candidate needs.

  • 02

    Name the ask

    You write the questions. A reviewer reads your ask before they open the build, which keeps the reply about the part you are unsure of rather than the part that is easiest to comment on.

  • 03

    Ship it, then say so

    Turn a note into a change and move it from open to shipped. The reviewer who raised it is told when it moves. Six notes have been marked shipped by the creators who got them.

Specification

Contrast ratios are computed, not estimated, using the WCAG 2.x relative-luminance formula. Where four numbers are given they are the ratio against --paper-hi / --paper / --paper-sub / --paper-deep, in that order. Body text floor is 4.5:1; large text, icons and control boundaries floor at 3:1. Every pair below clears its floor in both themes.

Font stacks

Chrome & display"Bricolage Grotesque", "Helvetica Neue", Arial, sans-serif. variable, weights 200–800. Every machine-written word: nav, buttons, labels, counts, headlines, numerals. font-variant-numeric: tabular-nums is on globally so grit numbers and review counts align down a column.
Voice"Newsreader", Georgia, "Times New Roman", serif. Variable, optical sizing on. Every word a person wrote: the ask, feedback bodies, creator replies, bios, and the one editorial standfirst under each section headline. A serif paragraph inside a row is the signal that there is a human in there.

Spacing scale

4 · 8 · 12 · 16 · 24 · 32 · 48 · 64 · 96 · 128 · 192px, 4px base. Section padding is 96 or 104 vertical; the gutter is 80; the content measure is 1280. Prose caps at 60ch, UI text at 46ch.

Radius

0 · 2px · 50%0 is the default and covers panels, bands, the media stage, the film panels and every rule. 2px is for controls, chips, avatars and the reviewer marks on the disagreement axis. 50% is used once, for the 7px live dot. There is no large rounded rectangle anywhere in the system, and nothing is a full pill.

Border & shadow

Hairline1px --rule. Decorative separation only. Never the only edge of a control.
Control edge1.5px --rule-2, ≥3:1 on all four surfaces (SC 1.4.11).
Structural edge1.5px --ink. Marks a thing you can act on: the proof panel, the feedback note, the media stage, the top of the stat table.
GradientNone, in the colour sense. The only repeating-linear-gradient in the file draws 1px rule fields inside the media stage, which is a hatch, not a colour ramp. No text gradient, no background bloom, no glass.
ShadowNone. Zero box-shadows are used for elevation anywhere in the system. Elevation is carried by surface tone and rule weight, which is why the light theme holds up. The only box-shadow in the file is an inset 2px underline on secondary-button hover.
Focus2px solid --ink at 3px offset, in both themes. Never the mark colour, so focus is never confused with severity.

Motion

120mscubic-bezier(.2,0,0,1) for colour and border changes on hover, link underline weight.
180mscubic-bezier(.2,0,0,1) for row hover fills, chip state.
240mscubic-bezier(.2,0,0,1) entrance ceiling; exits run at 120ms with cubic-bezier(.3,0,.6,1). One transition per view.
NeverNo scroll-triggered reveals, no parallax, no number counters, no motion over 240ms. All of it respects prefers-reduced-motion.

Target size

44 × 44Minimum for every control, with ≥8px between adjacent targets. Buttons are 48px tall; small buttons keep a 44px hit area via padding.
